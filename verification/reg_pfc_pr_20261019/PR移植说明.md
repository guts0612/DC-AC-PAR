# REG_PFC28379D 的 PR 移植到 DC-AC-PAR

已将 `REG_PFC28379D.zip/REG_LED_BLINK/USER/PR.c` 的 PR 系数和递推算法接入当前 Keil 工程的主机、从机电流内环。原文件只是一个独立的数学控制器，可以用于逆变器；PFC 的直流电压外环、交流电流参考生成和 PWM 控制方向需要按逆变器结构处理。

此次替换便于直接对照压缩包实现和实测结果。两种写法在理想精度、未限幅时对应同一传递函数；替换不构成原写法有误的证据，也不能直接证明空载自激已经消除。

修改前的文件备份在 [DC-AC-PAR_before_archive_pr_20261019_034137](D:/study/hal/backups/DC-AC-PAR_before_archive_pr_20261019_034137)。压缩包 PR 原始字节保存在本目录 `original/`，修改前控制器保存在 `previous/`，来源与哈希见 `source_manifest.json`。

压缩包怎样实现 PR

它实现的是带有限谐振带宽的准 PR（QPR）：

\[
G_{PR}(s)=K_p+\frac{2K_r\omega_c s}{s^2+2\omega_c s+\omega_0^2}
\]

- `Kp` 是比例增益；当前内环的输入为电流误差 A、输出为校正电压 V，因此增益按 V/A 理解。
- `Kr` 设置谐振增益；连续公式在中心频率处的总增益为 `Kp+Kr`。
- `W0=2πf0` 是中心角频率，50 Hz 对应约 314.159 rad/s。
- `Wc` 控制谐振带宽，单位 rad/s；原包和本机均为 5 rad/s。这个有限增益 QPR 本身不保证零稳态误差。

将 `s=(2/Ts)(1-z^-1)/(1+z^-1)` 代入，得到直接 I 型二阶递推：

\[
u[k]=-B_1u[k-1]-B_2u[k-2]+A_0e[k]+A_1e[k-1]+A_2e[k-2]
\]

原包 `PR_update()` 的核心就是：

```c
PR->Vo = (-PR->B1 * PR->Vo1) - (PR->B2 * PR->Vo2)
       + (PR->A0 * PR->Vi) + (PR->A1 * PR->Vi1) + (PR->A2 * PR->Vi2);
PR->Vo2 = PR->Vo1;
PR->Vo1 = PR->Vo;
PR->Vi2 = PR->Vi1;
PR->Vi1 = PR->Vi;
```

调用前 `Vi1/Vi2` 和 `Vo1/Vo2` 分别表示前两拍误差和输出。更新结束后历史向后移动一拍，为下一次计算准备数据。`A0/A1/A2` 已经包含比例项，外部若再加 `Kp*error`，会重复计算比例控制。

`B0` 仅用于初始化归一化。若记 `D=4+4Wc*Ts+W0²*Ts²`，其等价系数为：

\[
\begin{aligned}
A_0&=(4K_p+4\omega_cT_s(K_p+K_r)+K_p\omega_0^2T_s^2)/D\\
A_1&=(-8K_p+2K_p\omega_0^2T_s^2)/D\\
A_2&=(4K_p-4\omega_cT_s(K_p+K_r)+K_p\omega_0^2T_s^2)/D\\
B_1&=(-8+2\omega_0^2T_s^2)/D\\
B_2&=(4-4\omega_cT_s+\omega_0^2T_s^2)/D
\end{aligned}
\]

代码保留原包含 `1/Ts²` 的表达式和计算顺序，仅显式写出原来隐含的 double 类型转换，消除 ARMCC 的精度提升警告。系数只在初始化时计算；每拍 `PR_update()` 使用 float 乘加和历史移位。

与原项目的差别

| 项目 | 修改前 DC-AC-PAR | 本次移植 |
|---|---|---|
| 控制传递函数 | 上述准 PR | 相同 |
| 离散方法 | Tustin | Tustin |
| 递推状态 | 谐振分支的 r、q 双状态 | 前两拍误差和完整 PR 输出 |
| 比例项 | 外部 `Kp*error+r` | 合入 A0/A1/A2 |
| 实时精度 | float | float |
| 物理输入/输出 | 电感电流误差 A → 校正电压 V | 相同 |
| 主机限幅时 | 保留未限幅内部状态 | 保留未限幅输出历史 |
| 从机抗饱和 | 有条件冻结 r/q，仍更新上一拍误差 | 有条件冻结整组输入/输出历史 |

从机的饱和处理是对新状态结构的适配，饱和时不宣称与旧双状态实现逐拍等价。误差继续推动饱和时冻结，否则允许更新。主机仍可能在持续饱和时积累过大的内部响应，压缩包的 PR 本身也没有抗饱和算法。

验证时还发现：原从机用 `bridge-(bridge/bus)*bus` 判断是否继续推动调制度饱和。即使没有限幅，这个表达式也可能因 float 舍入不为零，使状态误冻结。本次增加“确实发生调制度限幅”的判断后，再判断误差方向。当前主机单独运行不经过这条从机路径，不能用这一发现解释此前主机空载自激。

PFC 为什么能移植、哪些设置需要适配

压缩包 `USER/main.c` 第 95 行初始化：

```c
PR_init(&PRA, 0.000025, 7.5, 95.0, 5.0, 314.15926535);
```

第 198～206 行先由 `100-Udc` 经 PI 生成电流幅值，再用 `Iref=PIout*Vac*0.01` 生成交流电流参考；PR 输入为 `Iref-Iac`，PWM 使用 `(Vac-PRA.Vo)/Udc`。

PR 数学函数没有 TI 寄存器、PFC 状态机或特定外设依赖。本机同样需要跟踪 50 Hz 电流，所以可以复用。PR 用于单相电压源逆变器也有公开实现，见 [imperix 的 PR 控制器技术说明](https://imperix.com/doc/implementation/proportional-resonant-controller)。

| 参数/连接 | 原 PFC | 本次逆变器 |
|---|---|---|
| PR 采样周期 | 25 μs，按 40 kHz 设计 | 从实际 HRTIM 控制频率生成，当前 50 μs / 20 kHz |
| Kp、Kr | 7.5、95 | 保留保存源码中的 3、21 |
| Wc、f0 | 5 rad/s、50 Hz | 5 rad/s、50 Hz |
| 电流指令来源 | 直流母线外环与 Vac | 主机电压误差经虚拟导纳；从机沿用电流分配 |
| 桥电压指令 | Vac 减 PR 输出 | 沿用本机电压前馈加 PR 校正 |

两个桥电压公式的符号关系与电流定义、变换器方向和 PWM 映射有关，不能只看到 PFC 有一个减号就复制过来。这里保留本机既有反馈方向。

主机链路仍为：电压误差 → 原有 DC 分量补偿 → 虚拟导纳 `1/(Lv*s+Rv)` → 电流参考 → 电流误差 → PR → ±5 V 校正限幅 → 加正弦电压前馈 → 除实测母线 → ±0.95 调制度限幅。24 Vrms 目标、ADC 标定、HRTIM 时序与遥测通道定义均按当前源码使用。

你曾在实物测试 Kp=1、Kr=1.6，但本次开始时保存源码是 Kp=3、Kr=21。移植保留保存值；测试脚本在临时副本分别验证这两组参数，不会修改实际增益。增益入口在 [qpr_control.h](D:/study/hal/DC-AC-PAR/Core/Inc/qpr_control.h:8)。

验证结果和边界

`Tests/verify_archive_pr.py` 直接编译压缩包未修改的 PR.c、本次控制器和修改前控制器。在 20 kHz、两组增益下，检查 DC、49、50、51、150、1000、5000 Hz，共 28 组响应；每组运行 5 s，最后 1 s 计算幅相。新主机和从机未限幅时均与原包逐拍一致，也检查了冲激、阶跃、混合输入、独立状态、复位、开环清状态、正负限幅、从机冻结及反向恢复、非法输入和非有限状态。

同样的 0.1 A 峰值、50 Hz 输入，主机电流内环输出结果如下（这里是控制器响应，不是闭环逆变器电压）：

| Kp / Kr | 实现 | 50 Hz 增益 V/A | 相位 |
|---|---|---:|---:|
| 3 / 21 | 原双状态 | 24.00002772 | -0.064703° |
| 3 / 21 | 压缩包直接 I 型 | 24.00267360 | -0.109648° |
| 1 / 1.6 | 原双状态 | 2.60000495 | -0.045450° |
| 1 / 1.6 | 压缩包直接 I 型 | 2.60026202 | -0.467022° |

相同采样率和参数下，原双状态实现更接近高精度 Tustin 参考。直接 I 型在高采样率、窄谐振带宽下的系数和递推存在相消，float 舍入更明显。表中相位也包含 Tustin 频率映射及有限精度影响，不能把它全部解释成程序执行延时。更换写法并不自动增加相位裕度。

此外，主从控制集成、母线同拍采样、误差 DC 补偿、RMS、VOFA 打包和均值检查通过。两个旧测试对当前标定方式、CH5/CH6/CH7 定义的过时假设已更新，生产代码的采样与通道定义未因此修改。Keil ARMCC 5.06 update 7 编译：0 错误、0 警告，已生成固件。

可复核证据：`pr_port_results.json`、`verification_summary.json`、`keil_build.log`。`pr_arm_disassembly.txt` 显示 ARMCC 生成的 `PR_update()` 使用 F32 浮点指令，没有 double 运算调用；这仍不等于实测整个中断耗时。本次没有烧录，也没有测量硬件波形或包含 LC、采样/PWM 延时的闭环稳定裕度。若后续仍有空载自激，需要继续检查完整环路、限幅和实际时序，不能由“PR 已换成参考工程写法”推断问题已解决。
